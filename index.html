00Abstract

Advanced Air Mobility (AAM) vehicles will fly low over dense cities, where GNSS signals are blocked, reflected, or jammed. Certified operation requires an independent way to know where the aircraft is. This dissertation proposes a vision-based absolute positioning system that estimates the full 6-DoF position and attitude of an AAM vehicle from its onboard camera, using Korea's national 3D spatial data (NGII LoD1 building models and V-World 3D Tiles) as the reference map.

The system works coarse-to-fine. A visual place recognition (VPR) stage retrieves the reference views that match the current frame. A dense feature-matching stage then links image pixels to 3D points on the map, and a gravity-constrained, robust Perspective-n-Point (PnP) solver computes the metric pose. The pose is fused with inertial measurements in an Extended Kalman Filter (EKF). A lightweight texture-quality gate skips frames that cannot be matched reliably. The design targets onboard embedded hardware and the 300–600 m altitude band typical of urban AAM corridors.

Keywords — AAM/UAM, visual localization, visual place recognition, dense feature matching, PnP, 3D Tiles, GNSS-denied navigation, A-PNT

01Research motivation

Why an aircraft needs to see where it is

GNSS is the default position source for every aircraft, and it is also the weakest link at the altitudes where AAM will operate.

Urban canyons cause multipath and signal blockage, and GNSS jamming and spoofing incidents have grown sharply in recent years. Inertial navigation alone drifts without bound. Relative vision methods such as visual odometry (VO), visual-inertial odometry (VIO) and SLAM reduce the drift but cannot remove it, because they never reference the world frame.

Absolute visual localization closes that gap: if the aircraft can match what its camera sees against a geo-referenced map, it recovers its position in the world frame with no radio signal at all. Aviation authorities (FAA, EASA, NASA) and the Korean K-UAM roadmap all identify alternative positioning, navigation and timing (A-PNT) as a prerequisite for routine urban flight.

Why national 3D spatial data

Most published aerial localization work matches against 2D satellite orthophotos. At AAM altitudes over high-rise districts this fails geometrically: building tops are displaced from their footprints (relief displacement), so a 2D-to-2D homography cannot explain the image. Korea already maintains nationwide 3D building data through the National Geographic Information Institute (NGII) and the V-World platform. Using that 3D data as the reference map lets the system render what the camera should see from any candidate viewpoint and solve the pose with true 2D–3D geometry.

Practical constraints

  • Onboard compute. The full pipeline must run on Jetson-class hardware under size, weight and power (SWaP) limits.
  • Integrity. Certification needs the system to know when it is wrong, not only to be accurate on average.
  • Cross-domain imagery. Live oblique camera frames differ from rendered or satellite reference imagery in season, lighting and viewpoint.

02Research content and contributions

C1Hierarchical coarse-to-fine framework. A complete pipeline from image retrieval to metric 6-DoF pose, designed around national 3D spatial data served as a localization reference service.
C2Reference-data strategy for 300–600 m flight. A systematic comparison of 2D↔2D, 2D↔3D and 3D↔3D reference combinations, establishing render-based 2D↔3D PnP as the primary path and the others as fallbacks.
C3Texture-quality gating. A fast cascade detector that rejects low-texture frames (water, uniform roofs, fields) before matching, saving compute and preventing false fixes.
C4Robust, gravity-constrained pose estimation. Two independent robust-estimation stages (matching and PnP) using MAGSAC++ and graduated non-convexity (GNC), with the IMU gravity vector reducing the pose search space.
C5Embedded deployment. Distilled foundation-model backbones (DINOv3 ViT/ConvNeXt variants) selected for Jetson-class inference and quantization robustness.

03Method

Coarse-to-fine visual localization

Each incoming camera frame passes through four stages. Only frames that pass the texture gate reach the expensive matching steps, and the EKF keeps a continuous pose estimate between successful visual fixes.

Stage 0 — Texture-quality gate

A cascade detector built on Sobel gradient statistics estimates how much matchable structure a frame contains. Water bodies, uniform rooftops and cloud-covered frames are rejected in a few milliseconds. The classical operator was chosen deliberately for speed; a learned matchability predictor is a drop-in alternative.

Stage 1 — Visual place recognition (coarse)

A self-supervised foundation backbone (DINOv3, distilled for embedded use) extracts dense patch features, and a VPR aggregator (SALAD, BoQ or SelaVPR) pools them into a single global descriptor. The descriptor is compared against a pre-built database of geo-tagged reference views to produce a short list of candidate locations. The EKF prior limits the search to a plausible radius.

Stage 2 — Dense feature matching (fine)

For each candidate, the query frame is matched against a reference rendered from the 3D map at a nearby viewpoint. A dense matcher (RoMa v2) returns pixel correspondences with confidence. Because every rendered pixel carries a depth value, each match becomes a 2D–3D correspondence in the world frame. A first robust-estimation pass removes geometrically inconsistent matches.

Stage 3 — Robust, gravity-constrained PnP

The IMU provides roll and pitch with good accuracy, so the solver only needs to estimate position and heading. This reduces the problem from six to four degrees of freedom, improving both speed and robustness. MAGSAC++ and graduated non-convexity reject the remaining outliers. The matching-stage and PnP-stage robust estimators are not redundant: the first filters wrong correspondences, the second filters correspondences that are locally plausible but globally inconsistent with a single camera pose.

EKF fusion

Visual fixes arrive intermittently. An Extended Kalman Filter propagates the state with IMU data between fixes, updates it when a fix arrives, and uses the innovation to flag fixes that disagree with the motion model.

04Reference map design

Three ways to pair the query with the map

The choice of reference data decides which geometry the solver can use. The dissertation compares three combinations for the 300–600 m altitude band.

Fallback

2D ↔ 2D homography

Query against orthophotos. Simple and fast, but relief displacement of tall buildings violates the planar assumption in dense urban areas.

Primary

2D ↔ 3D render + PnP

Query against views rendered from 3D Tiles with per-pixel depth. Handles building height correctly and gives a full metric pose.

Fallback

3D ↔ 3D registration

Reconstructed local point cloud aligned to the 3D model with a rigid transform. Useful when single-frame matching is weak.

Reference data is drawn from V-World 3D Tiles (served in EPSG:3857 / ECEF) and NGII LoD1 building models (native EPSG:5179). All data is transformed into a single local frame. The roughly 60–75 cm offset between geodetic datums is corrected explicitly, since it is of the same order as the target accuracy.

Findings

  • Render-based 2D↔3D matching remains valid over high-rise districts where the 2D orthophoto baseline breaks down because of relief displacement.
  • The texture gate removes frames that would otherwise produce confident but wrong fixes.
  • The gravity constraint reduces PnP to four unknowns, which lowers the number of inliers needed for a stable solution.
